Closes #67

## What changed
- tightened Support Workbench webhook diagnostics so raw webhook bodies are only surfaced when the body hash is tied to a known-target signature diagnostic with `signatureMatched: true`; missing-signature, invalid-signature, and unknown-target diagnostics now stay redacted while still exposing safe metadata such as byte count, hash, and trust-gate context
- bounded each current queue with the same limit semantics as `matchingAttempts` and added queue-total metadata so the admin UI can show when a queue is truncated
- made support scheduled-date filters deterministic by normalizing timezone-less `datetime-local` values to UTC in the admin UI and parsing timezone-less API filter values as UTC on the server

## Why it changed
- support admins need enough webhook evidence to troubleshoot trusted CloudShare deliveries without reflecting arbitrary untrusted request bodies back into the UI
- active queue payloads need the same guardrails as the cross-status attempt search to avoid returning thousands of current attempts in one response
- the support filters are labeled UTC, so their serialization and parsing must not drift with browser or server local time

## Tests added or updated
- `src/api/support-workbench.test.ts` now covers untrusted webhook-body redaction, bounded current queues with queue metadata, and timezone-less UTC filter parsing
- `src/web/admin-console-state.test.ts` now covers UTC serialization of timezone-less support filter inputs
- full checks passed: `npm run lint`, `npm run typecheck`, `npm test`

## Risks or follow-up work
- trusted raw-body display currently depends on the matching signature-diagnostic record being present in the scanned support-log window; if operators need longer-lived HMAC evidence, the next slice should persist a dedicated trusted webhook diagnostic view instead of relying on recent logs alone
- the support filters use the existing single-page admin console; a later slice could extract a dedicated support-workbench client/state module if this area keeps growing
- human QA is still needed for the user-visible admin flow before merge
