    NOTE:** We are also in the process of delivering our Workato-embedded integration platform, which provides a no-code/low-code solution for integrating external systems with CloudShare and other third-party applications. I think building a recipe within the embedded Workato platform could be of great benefit to you guys. The feature is in alpha at the moment, and we should deliver it as a beta very soon.
1.  APIv4 - Create Training Experience [4]: This is the wrapper into which you would add a participant and schedule the access to the environment. You could use this in a few ways, but I do know that customers who use our platform to deliver certifications create experiences and map them one-to-one to a user. In this way, each experience is segregated, and the start time is unique for that specific user. As long as the experience is created five hours before the participant logs in, then the environment will be ready to go.
2.  APIv4 - Add Training Students [5]: This may not be required, depending on use case, as the "Create Sponsored Link" endpoint can also register a participant.
3.  APIv4 - Add a User Property to a Training [6]: potentially required to add additional fields for a user, typically a licence key, external credential, etc.
4.  APIv4 - Create Sponsored Link [7]: This is your secret source for creating a participant registration and returning a URL that redirects the participant directly to their environment within CloudShare, without needing to log on through the CloudShare portal.
5.  APIv3 - Suspend an environment [8]
6.  APIv3 - Resume an environment [9]
7.  APIv3 - Extend an environment [10] (unsure if you would require this).
8.  Event - Environment Created: Fires when an environment is created.
9.  Event - Environment Suspended: Fires when an environment is suspended.
10.  Event - Environment Resumed: Fires when an environment is resumed.
I think this should get you started on seeing the art of the possible, but I'm sure there are many more niche use cases you might think of.
